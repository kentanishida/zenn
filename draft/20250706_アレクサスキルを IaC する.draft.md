Alexa のスキル開発において、GUI で操作するのが面倒だったので github actions を用いて自動でデプロイする仕組みを作りました。

## 想定読者

- Alexa のスキル開発をしていて、毎度 alexa のデベロッパーコンソールから操作するのが面倒な人
- IaC したい人

## おことわり

- この PJT では、確かに ask deploy を用いて　github でデプロイをしていますが、カスタムスキルの backend である Lambda のデプロイを別のフレームワークに任せていたため、その切り離しを行っています

- alexa スキル自体は lambda で動いていますが、lambda は serverless-framework（ここリンクつける） で既にデプロイしていたので、設定だけ切り離して行いたかった
- alexa スキル自体の仕様上、AccountLinking 機能（Oauth での連携）も合わせてデプロイしたかった

## 📂 プロジェクト構成

プロジェクト構成は以下の通りです。この記事では特に、デプロイ用の設定がある `.github/workflows/` と alexa skill の設定がある `infrastructure/ask/` に焦点を当てて解説します。

```text:プロジェクト構成
.
├── .github/workflows/      # 🚀 GitHub Actions ワークフロー
│   ├── _deployAlexa.yml              # Alexa スキルをデプロイするためのもの。再利用できるようにしている
│   ├── ciForMaster.yml               # masterブランチへの push 時に実行されるCI（alexa のデプロイ機能を含む）
├── infrastructure/
│   └── ask/
│       ├── .ask/                     # ASK CLIが自動生成する状態管理ファイル。手動では触らない
│       ├── skill-package/
│       │   ├── skill.json            # スキルの公開情報やAPIのエンドポイントを定義
│       │   ├── accountLinking.json   # アカウントリンキング（oAuth）の設定を定義
│       │   └── interactionModels/
│       │       └── custom/
│       │           └── ja-JP.json    # 対話モデル（インテント、スロットなど）を定義
│       │           └── ja-JP.json    # 対話モデル（インテント、スロットなど）を定義
│       └── ask-resources.json        # ASK CLIが使用するプロファイル設定
... 以下略
```

## Alexa スキルの設定ファイルについて

ファイルは ○つあります

### `ask-resources.json`

ASK CLI が使用するプロファイル情報を定義します。
（ここ赤字）ここでの一番大事な注意点は、profile に `__ENVIRONMENT_ASK_PROFILE__` を指定しないといくら command 実行時に環境変数（言葉の正しさを確認）を渡しても全く上書きされません。

```json:infrastructure/ask/ask-resources.json
{
  "askcliResourcesVersion": "2020-03-31", // ASK CLI リソース定義スキーマのバージョン。 2020-03-31 の指定一択らしい
  "profiles": { // デプロイするプロファイル毎の設定を記載。
    "local": { // プロファイル名
      "skillMetadata": { // スキルメタデータ（どこの設定ファイルを参照させるのか）の設定を記載
        "src": "./skill-package" // このプロファイルが参照するスキルパッケージのパス
      }
    },
    "__ENVIRONMENT_ASK_PROFILE__": { // CI/CD でデプロイに関わるキーを command で指定する時に使うプロファイル名。この文字列を書かないと command で指定した profile を読み込んでくれない
      "skillMetadata": {
        "src": "./skill-package" // local 実行と別のものを指定する必要がないので同じものを指定する
      }
    }
  }
}
```

### `skill.json`

スキルの公開情報や、バックエンドとなる Lambda のエンドポイントを定義します。
（これ赤字にする）スキル開発をする際、Lambda の統合は ARN の指定か HTTPS の指定かどちらかを選べるかと思いますが、今回 Lambda は別のフレームワークでデプロイしたかったため、より一般的な企画である HTTPS での統合の方針を取りました。やっていないのでわかりませんが、もしかすると ARN で指定して ask で Lambda もまとめてデプロイした方が楽だったかもしれません。

```json:infrastructure/ask/skill-package/skill.json
{
  "manifest": { // スキルのメタデータ全体を定義するルートオブジェクト。おまじないの認識で OK
    "apis": { // スキルが利用する API の定義
      "custom": { // カスタムスキル向け設定。他にも色々な種類があるが、バックエンドを別で構えて何かをするなら基本これ
        "endpoint": { // スキルが呼び出すエンドポイント設定
          "uri": "https://example.com", // リクエストを受ける エンドポイントの URL。HTTP は対応していません。
          "sslCertificateType": "Trusted" // 使用する証明書の種類（ACM で証明書を発行している場合はこれ）
        },
... CI に関係ない部分なので以下略
      }
    }
  }
}
```

### `accountLinking.json`

OAuth によるアカウント連携（アカウントリンキング）の設定です。秘匿情報のため `clientId`と`clientSecret`はデプロイ時に github actions の secrets から動的に設定されます。

Oauth の機能を使わない方は読み飛ばしてください。

```json:infrastructure/ask/skill-package/accountLinking.json
{
  "accountLinkingRequest": { // アカウントリンク設定の開始
    "type": "AUTH_CODE", // OAuth 認証コードグラント方式を使用
    "authorizationUrl": "https://example.com/oauth/authorize", // ユーザー認証用の認可エンドポイント URL
    "accessTokenUrl": "https://example.com/oauth/access_token", // 認可コードをアクセストークンに交換するエンドポイント URL
    "clientId": "overrideAtDeployment", // oAuth の clientId。デプロイ時にGithub secrets で上書きする
    "clientSecret": "overrideAtDeployment", // oAuth の clientSecret。デプロイ時にGithub secrets で上書きする
    "scopes": [ // 要求する OAuth スコープのリスト
      ...略
    ],
    "domains": [ // アカウントリンクで許可するドメイン
      "example.com" // Todoist API ドメイン
    ],
    "accessTokenScheme": "HTTP_BASIC" //認証に必要な情報を受け渡す方式を規定。form でも可能だが基本はこれ
  }
}
```

## github actions について

`master`ブランチにpushされると、`ciForMaster.yml`ワークフローが実行されます。このワークフローは、テストやフォーマットチェックの後、`_deployAlexa.yml`を呼び出してAlexaスキルのデプロイを行います。

### ワークフロー (`ciForMaster.yml`)

```yaml:.github/workflows/ciForMaster.yml
name: ciForMaster

on:
  push:
    branches:
      - master

jobs:

...中略

  deployAlexa: // これが今回作ったもの
    needs: [format-check-and-fix, lint-check, spec-test] // デプロイ前にテストの実行を保証するもの
    uses: ./.github/workflows/_deployAlexa.yml
    permissions:
      contents: write
      pull-requests: write
    secrets:
      ASK_ACCESS_TOKEN: ${{ secrets.ASK_ACCESS_TOKEN }}
      ASK_REFRESH_TOKEN: ${{ secrets.ASK_REFRESH_TOKEN }}
      ASK_VENDOR_ID: ${{ secrets.ASK_VENDOR_ID }}
      OAUTH_CLIENT_ID: ${{ secrets.OAUTH_CLIENT_ID }}
      OAUTH_CLIENT_SECRET: ${{ secrets.OAUTH_CLIENT_SECRET }}

...以下略
```

### デプロイ用のワークフロー (`_deployAlexa.yml`)

実際に Alexa スキルのデプロイとアカウントリンキング設定の更新を行うものです。この PJT では別のワークフローから呼び出していますが内容はコピペで使えるはず。

```yaml:.github/workflows/_deployAlexa.yml
name: deployAlexa

on:
  workflow_call:
    secrets:
      ASK_ACCESS_TOKEN:
        required: true
      ASK_REFRESH_TOKEN:
        required: true
      ASK_VENDOR_ID:
        required: true
      OAUTH_CLIENT_ID:
        required: true
      OAUTH_CLIENT_SECRET:
        required: true

permissions:
  contents: write
  pull-requests: write

jobs:
  deployAlexa:
    name: deployAlexa
    runs-on: ubuntu-latest
    concurrency:
      group: deployAlexa
      cancel-in-progress: false
    steps:
      - name: Checkout repo
        uses: actions/checkout@v4

      - name: Install Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 22
      
      - name: Install ask-cli
        run: npm i ask-cli -g # asl-cli はグローバルインストール推奨なのでそれに則る

      # config を作るため jq をインストールする
      - name: Install jq
        run: sudo apt-get install -y jq

      - name: Create ask config using jq
        env:
          ASK_ACCESS_TOKEN:  ${{ secrets.ASK_ACCESS_TOKEN }}
          ASK_REFRESH_TOKEN: ${{ secrets.ASK_REFRESH_TOKEN }}
          ASK_VENDOR_ID:     ${{ secrets.ASK_VENDOR_ID }}
        run: |
          mkdir -p ~/.ask
          jq -n \
            --arg accessToken "$ASK_ACCESS_TOKEN" \
            --arg refreshToken "$ASK_REFRESH_TOKEN" \
            --arg vendorId "$ASK_VENDOR_ID" \
            '{
              "profiles": {
                "__ENVIRONMENT_ASK_PROFILE__": {
                  "token": {
                    "access_token": $accessToken,
                    "refresh_token": $refreshToken
                  },
                  "vendor_id": $vendorId,
                  "aws_profile": "free-pjt"
                },
                "free-pjt": {
                  "token": {
                    "access_token": $accessToken,
                    "refresh_token": $refreshToken
                  },
                  "vendor_id": $vendorId,
                  "aws_profile": "free-pjt"
                }
              }
            }' > ~/.ask/cli_config

      - name: Deploy Alexa Skill
        env:
          ASK_DEFAULT_PROFILE:  free-pjt
          ASK_ACCESS_TOKEN:     ${{ secrets.ASK_ACCESS_TOKEN }}
          ASK_REFRESH_TOKEN:    ${{ secrets.ASK_REFRESH_TOKEN }}
          ASK_VENDOR_ID:        ${{ secrets.ASK_VENDOR_ID }}
        run: cd infrastructure/ask && ask deploy --profile __ENVIRONMENT_ASK_PROFILE__ --debug

      - name: Deploy Account Linking
        env:
          ASK_DEFAULT_PROFILE:  free-pjt
          ASK_ACCESS_TOKEN:     ${{ secrets.ASK_ACCESS_TOKEN }}
          ASK_REFRESH_TOKEN:    ${{ secrets.ASK_REFRESH_TOKEN }}
          ASK_VENDOR_ID:        ${{ secrets.ASK_VENDOR_ID }}
          OAUTH_CLIENT_ID:    ${{ secrets.OAUTH_CLIENT_ID }}
          OAUTH_CLIENT_SECRET: ${{ secrets.OAUTH_CLIENT_SECRET }}
        run: |
          cd infrastructure/ask
          
          # secret を使用するため skill-package 外部（/tmp）で動的に作成する
          jq -c \
            --arg clientId "$OAUTH_CLIENT_ID" \
            --arg clientSecret "$OAUTH_CLIENT_SECRET" \
            '.accountLinkingRequest.clientId = $clientId | .accountLinkingRequest.clientSecret = $clientSecret' \
            ./skill-package/accountLinking.json > /tmp/accountLinking_generated.json

          SKILL_ID=$(jq -r '.profiles."__ENVIRONMENT_ASK_PROFILE__".skillId' .ask/ask-states.json)
          echo "Deploying account linking for skill: $SKILL_ID"

          # 必須属性の -g には開発環境ではなく、alexa の公開状況を指す情報を入れる（development: 開発中、certified:審査完了・公開待ち、live:公開中）
          ask smapi update-account-linking-info \
            -s "$SKILL_ID" \
            -g "development" \
            --profile __ENVIRONMENT_ASK_PROFILE__ \
            --account-linking-request "$(cat /tmp/accountLinking_generated.json)" \
            --debug
          
          # この後の commit に巻き込まれないように一時ファイルを削除しておく
          rm -f /tmp/accountLinking_generated.json

      # デプロイが完了した場合、.ask/ask-states.json が書き換わるので、直接 commit してブランチにプッシュする
      - name: Get git author info
        id: get_author
        run: echo "author=$(git log -1 --pretty=format:'%an <%ae>')" >> $GITHUB_OUTPUT

      - name: Commit and push changes
        # PR の作成が無限ループしないようにするため
        if: steps.get_author.outputs.author != 'gha-deploy-alexa[bot] <bot@nishiken.me>'
        run: |
          git config user.name "gha-deploy-alexa[bot]"
          git config user.email "bot@nishiken.me"
          git add .
          if git diff --staged --quiet; then
            echo "No changes to commit"
          else
            # master ブランチの場合はPRを作成、他のブランチは直接プッシュ
            if [ "${{ github.ref_name }}" = "master" ]; then
              BRANCH_NAME="bot/alexa-deploy-$(date +%Y%m%d-%H%M%S)"
              git checkout -b "$BRANCH_NAME"
              git commit -m "[bot] fix .ask/ask-states.json to update hash after deploying alexa"
              git push origin "$BRANCH_NAME"
              
              # GitHub CLI でPR作成
              gh pr create \
                --title "[bot] Update Alexa skill deployment state" \
                --body "Auto-generated PR to update .ask/ask-states.json after Alexa skill deployment" \
                --base master \
                --head "$BRANCH_NAME"
            else
              git commit -m "[bot] fix .ask/ask-states.json to update hash after deploying alexa"
              git push origin ${{ github.ref_name }}
            fi
          fi
        env:
          GH_TOKEN: ${{ github.token }}
```
